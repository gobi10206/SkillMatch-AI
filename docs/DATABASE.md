# Database — SkillMatch AI

PostgreSQL 15+ with the `pgvector` extension (the `ankane/pgvector`
Docker image used in `docker-compose.yml` ships both).

## Running migrations

```bash
docker compose up -d db
cd backend
alembic upgrade head
```

This creates the `vector` and `uuid-ossp` extensions and every table
listed below (see `alembic/versions/0001_initial.py`).

## Schema overview

| Table | Purpose |
|---|---|
| `users`, `audit_logs` | accounts, RBAC role, sensitive-action log |
| `profiles`, `experiences`, `education`, `projects` | seeker profile data, incl. informal/freelance experience |
| `skills`, `user_skills`, `skill_evidence` | taxonomy, a user's skills (AI-inferred vs verified), and the source text behind each inference |
| `careers`, `career_skills` | target careers and their required/optional skills |
| `companies`, `jobs`, `job_skills` | employer-posted roles and requirements |
| `applications`, `matches` | seeker application tracker and cached explainable match results |
| `courses`, `course_skills`, `certifications` | learning resources |
| `learning_paths`, `learning_modules`, `learning_progress` | personalized, step-based learning plans |
| `fairness_survey`, `fairness_metrics` | isolated voluntary demographic data and aggregated fairness stats — see below |

## Fairness isolation (schema-level)

`fairness_survey` is the only table that may hold demographic data,
and it is linked to the rest of the schema **only** by `user_id`.
No ranking or matching query (`matches`, `user_skills`, `career_skills`,
`job_skills`) joins against it. Only the fairness-metrics service
(Phase 13/22) is expected to read `fairness_survey`, and only to
compute aggregated statistics written into `fairness_metrics`.

## Creating a new migration

After changing a model in `app/models/`:

```bash
cd backend
alembic revision --autogenerate -m "describe the change"
alembic upgrade head
```

Always review autogenerated migrations before applying — autogenerate
does not reliably detect column type changes or renames.
